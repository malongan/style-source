## style-source 变量整改（分支 fix/variables-spec-compliance）

**背景**：style-source 作为「风格库」插件接入无限画布（iwb-plugins/style-source，v1.0.3）。
插件侧已完整实现变量替换，问题全在数据侧：插件不校验、不报错，写错了只在用户手里暴露。

**整改结果**（audit_variables.py）：
- 声明落空 271 条 / 34 个风格 → 0
- 值写成描述 430 条 → 0
- 标签带反引号 392 条 → 0
- 补零声明 671 条，声明命中 699 → 1411

**关键决策（有长期价值）**：
1. **不用 yaml.dump 回写**。ruamel round-trip 会统一缩进、把折行 prompt 合并成一行，
   310 个文件全是假 diff。改用文本级编辑，只替换占位符与 variables 段。
2. **比例槽位不硬删，改用 `ratio:` 字段值替换**。中文句「生成一张{比例}的饮品图」
   硬删会变「生成一张的饮品图」；替换成「生成一张16:9的饮品图」才通顺。
3. **替换必须限制在 prompt 块内**。全局替换会把 features 里的 `[TITLE]` 也改成花括号
   （那是给人读的介绍）。
4. **技术槽位（STYLE_FIDELITY_ANCHORS / SOURCE_CONTENT_TO_AVOID）转常量文本**，
   直接删会留下「anchors: .」残句。
5. **脏槽位不补声明**：`{填写主题，例如：…}` 这类说明书式占位符，补了只会得到巨长标签，
   留给人工改 prompt。

**闸门**：
- validate_style.py 加 check_variables_semantics()：R1/R2 为 error，R3 为 warning
  （15 处脏槽位待人工改 prompt，暂不阻塞）
- on-push-styles / on-merge-main 接入 audit_variables.py --strict
- 顺序陷阱：audit 读的是 data/styles.json 生成物，必须先 generate_data

**遗留**：
- 15 处脏槽位（6 个风格）需改 prompt
- 纯英文标签 608 条（117 个风格），LABELS 映射表覆盖不足
- 90 个风格变量超过 8 个（spec 建议上限），多为 Vigo 模板类
- 76 个风格已无变量（纯风格演示，符合 spec B4 判断）

**工具**：scripts/migrate_variables_spec.py（默认 dry-run，--apply 才写回）
