# 提示词变量规范（PROMPT_VARIABLES_SPEC）

> 适用对象：向本仓提交风格 YAML 的 Agent / 人。
> 本文是 `AGENT_SETUP.md` 4.3 节的**强制补充**：那份模板只规定了「形态」，本文规定「语义」。
> 基线数据：2026-11-02，310 个风格（`python3 scripts/audit_variables.py` 现场复核，勿照抄数字）。
>
> 一句话：**变量不是写给人看的说明书，是提示词里的可替换槽位。**

---

## 0. 三条铁律

| # | 规则 | 违反后果 |
|---|---|---|
| **R1** | 每个 `variables` 条目，其占位符必须**原样出现在 `prompt` 里** | 用户看得见输入框，填了却毫无反应 |
| **R2** | `style_var` 写**占位符本体**（`"{主体}"`），不写描述、不写候选清单 | 同上，且标签会变成一句怪话 |
| **R3** | 想让用户填什么，就在 `prompt` 里写 `{槽位}`；**不写槽位，就永远不会有输入框** | 用户抱怨「这个风格没有变量可填」 |

R3 是当前最主要的问题来源，见第 6 节统计。

---

## 1. 唯一真理源

插件（以及未来的任何消费方）只会做一件事：

```
扫描 prompt 文本里所有 /(\{[^{}\n]{1,40}\})/  →  生成输入框  →  插入时字符串替换
```

`variables` 只负责回答一件事：**这个槽位在面板上叫什么中文名、示例填什么**。

所以：

- `prompt` 里没有 `{xxx}` ⇒ 这个风格就是零变量，谁也没法变出输入框；
- `variables` 里写了但 `prompt` 里没有 ⇒ 这条声明是**死条目**，必须删掉或把槽位补进 prompt；
- 两边对不上时，插件会退化成「用占位符名当标签」——能用，但用户看到的是 `brand_name` 这种英文，体验差。

---

## 2. 三条硬规则的写法

### R1：一对一，字面量完全相同

```yaml
prompt: |
  一张{主体描述}的 X 光扫描图，骨骼以霓虹青色发光，背景为{背景色}。

variables:
  - kv_var: 主体描述
    style_var: "{主体描述}"      # ← 与 prompt 里一字不差
    desc: "如：一只猫、一台相机"
  - kv_var: 背景色
    style_var: "{背景色}"
    desc: "如：哑光黑、深空蓝"
```

不要出现「`{主体}` 声明成 `{主体对象}`」这种一字之差；不要把全角括号 `｛主体｝` 当占位符（不认）。

### R2：`style_var` 只能是占位符本体

| 写法 | 判定 |
|---|---|
| `style_var: "{主体描述}"` | ✅ 唯一正确形态 |
| `style_var: "主体描述"`（无括号） | ⚠️ 能命中（靠 key 兜底），但语义错，应改 |
| `style_var: "花体字内容，如'旷野的风'、'自由之路'"` | ❌ 这是 desc 内容，塞进了 style_var |
| `style_var: "3:4（手机壁纸）、16:9（横版海报）"` | ❌ 这是候选清单，用户没法选，等于没变量 |
| `style_var: ""` | ❌ 空值，生成脚本直接丢弃该条 |

想写示例？写进 `desc`：

```yaml
  - kv_var: 主标题
    style_var: "{主标题}"
    desc: '花体字内容，如"旷野的风"、"自由之路"'
```

### R3：先有槽位，才有变量

反面实例（本仓真实存在，`styles/creative/xray_scan.yaml`）：

```yaml
prompt: |
  An X-ray scan of a {主体对象}, bones and internal structures glowing ...
# ← 有 1 个槽位，但整个文件没有 variables
```

结果：插件只能用 `主体对象` 当标签。**这已经算好的**——它至少有槽位。真正无解的是：

```yaml
prompt: |
  An X-ray scan of a cat, bones glowing ...      # 主体写死成 cat
```

用户想换主体只能自己去改提示词。收集阶段就要把「使用者一定会换的名词」挖成槽位。

## 3. 什么该做成变量

判据只有一句：**换掉它，这个风格依然成立 ⇒ 该做成变量；换掉就不成立 ⇒ 它是风格本体，写成常量。**

### 该做（按优先级）

| 优先级 | 类别 | 示例 | 说明 |
|---|---|---|---|
| P0 | **主体** | `{主体对象}` `{人物描述}` `{产品}` | 几乎每个风格都该有；没有主体的风格用「场景」代替 |
| P1 | 主体的可变属性 | `{动作姿态}` `{服装}` `{配饰}` `{表情}` | 影响画面叙事，不是风格常量 |
| P2 | 场景 / 背景元素 | `{背景环境}` `{氛围元素}` `{季节}` | |
| P3 | 文案文字 | `{主标题}` `{副标题}` `{诗句}` `{品牌名}` | 海报/包装/社媒类必须有，且要给出「放哪里、多大」的上下文 |
| P4 | 画幅 / 尺寸 | `{画幅比例}` | 仅当提示词确实按比例构图时才给 |

### 不该做（写成常量，别给输入框）

| 类别 | 例子 | 原因 |
|---|---|---|
| 风格常量 | 配色方案、笔触、构图法、镜头、材质、光照 | 换了这个风格就不成立了 |
| 否定词 / 规避项 | `不要水印`、`避免写实摄影`、`avoid logos` | 用户不该也无法逐条开关 |
| 技术参数 | `{STYLE_FIDELITY_ANCHORS}`、`{SOURCE_CONTENT_TO_AVOID}`、`seed`、`steps` | 这是给模型看的元指令，不是给用户填的 |
| 已经被限定死的枚举 | 「3:4（手机壁纸）、16:9（横版）」塞进一个文本框 | 用户拿不到选择器，只能瞎猜格式 |
| 长句描述 | `{诗中景物构成的东方场景，如春日园林}` | 占位符名超过 40 字或含标点会被判为非法，直接不识别 |

> 例外：`{ASPECT_RATIO}` 这类英文占位符在 Vigo 批次里大量存在。**保留槽位，但必须补 `variables` 声明成「画幅比例」**，别让它以裸英文名出现在面板上。

## 4. 数量：3–6 个，最多 8 个

本仓实测分布（单位：风格数）：

| 占位符个数 | 0 | 1–2 | 3–6 | 7–13 | 14+ |
|---|---|---|---|---|---|
| 风格数 | 95 | 46 | 50 | 114 | 5 |

- **0 个**：95 个里 64 个确实无变量（纯风格演示，可接受），**31 个有声明却没槽位**——属于死声明，必须补槽位或删声明。
- **1–2 个**：46 个，偏少，通常只做了主体、漏了文案/场景，建议补到 3 个以上。
- **14+ 个**：只出现在 Vigo 模板类（5 个风格，最多 24 个），用户面对 24 个空框会直接放弃。面板会折叠前 6 个，但**源头就该砍到 8 个以内**。

推荐骨架（按分类选一套，不需要全部照搬）：

| 分类 | 建议变量 |
|---|---|
| 社交媒体 / 品牌KV | `主体` `主标题` `副标题` `品牌色` |
| 电商 / 印刷品 | `产品` `卖点文案` `背景场景` `画幅比例` |
| 编辑排版 / 字体排版 | `主标题` `正文摘句` `主体图像` |
| 时尚美容 / IP角色 | `人物描述` `服装造型` `妆容/表情` `背景环境` |
| 旅行城市 / 创意特殊 | `地点` `场景元素` `季节氛围` `主标题` |
| 科研专业 | `研究对象` `标注文字` `视图类型` |

## 5. 命名规范

| 项 | 规则 | 正例 | 反例 |
|---|---|---|---|
| 占位符名 | 中文短词（≤8 字）或 `UPPER_SNAKE_CASE`，**一个风格内不混用两种体系** | `{主体对象}`、`{SUBJECT}` | `{主体对象SUBJECT}`、`{主体-对象}` |
| 字符集 | 汉字 / 字母 / 数字 / 下划线；**不含**空格、引号、冒号、逗号、方括号、反引号 | `{brand_name}` | `{brand name}`、`{brand,name}` |
| 长度 | 建议 1–20 字符；**超过 40 直接不识别** | `{画幅比例}` | `{诗中景物构成的东方场景与人物关系}` |
| `kv_var` | 面板标签，干净中文，不带 markdown | `主体对象` | `` `SUBJECT` ``、`**主体**` |
| `desc` | 一句示例或取值范围，写给用户看 | `如：一只猫、一台相机` | 空 |

统一用**半角** `{` `}`。`[方括号]`、`（全角括号）` 一律不识别——本仓有 16 个风格在用 `[SQUARE]`，需批量转为花括号。

## 7. 收集流程（SOP）

顺序不能反。**先写死提示词再抽槽位**，不要「先列变量表再套进提示词」——后者就是 34 个死声明风格的成因。

1. **写 prompt**：把风格本身刻进文字（构图、配色、笔触、材质、光影、规避项），主体先写成**一个具体例子**（如 `a cat`）。
2. **标槽位**：逐个判断「这个名词换成别的东西，风格还成立吗？」成立 ⇒ 换成 `{中文短词}`。
3. **回读检查**：通读提示词，确认每个槽位在句子里位置合理、有前后文约束（例如不能只写 `{主标题}`，要写「左上角大幅中文标题`{主标题}`」）。
4. **写 variables**：顺序与提示词出现顺序一致；`style_var` = `"{槽位名}"`；`desc` 给示例。
5. **自检**（必须跑）：

```bash
python3 scripts/audit_variables.py --strict             # 有告警即退出码 1
python3 scripts/validate_style.py styles/{分类}/{id}.yaml
```

`--strict` 会把「声明落空」「值写成描述」「标签带反引号」都算失败，正是本次要清的三类问题。

6. **生成数据并复核**：`python3 scripts/generate_data.py` 后，确认该风格在 `data/styles.json` 里的 `variables` 非空且键名干净。

> 若无法本地跑脚本，提交前人工回答三个问题：
> ① 每个 `style_var` 是否能**复制粘贴**到 prompt 里搜到？② 每个 `{槽位}` 是否都有一条声明？③ 有没有哪条声明的值是一句人话/一串弹幕式枚举？

## 8. 建议给 CI 加的门禁（可选，但强烈建议）

现有 `validate_style.py` 只校验**结构**（是否 list、两字段是否必填、表头残留），因此「结构合法但语义无效」的 34 个风格能一路绿灯进主干。

建议在 `validate_style.py` 里补 3 条 `errors`（不是 warning）。下面是**示意**，接入时按该文件现有的 `data` / `errors` 变量名调整：

```python
prompt = str(data.get('prompt', ''))
declared = [v for v in variables if isinstance(v, dict)]

# 1) 声明的占位符必须在 prompt 里逐字出现
for v in declared:
    ph = str(v.get('style_var', '')).strip()
    if ph.startswith('{') and ph.endswith('}') and ph not in prompt:
        errors.append(f'style_var {ph} 未出现在 prompt 中（填了不会生效）')

# 2) prompt 里的每个槽位都必须有声明
for name in set(re.findall(r'\{([^{}\n]{1,40})\}', prompt)):
    if not any(name in (str(v.get('kv_var', '')), str(v.get('style_var', ''))) for v in declared):
        errors.append(f'prompt 槽位 {{{name}}} 没有对应 variables 声明')

# 3) 拒绝候选清单式的 style_var
for v in declared:
    sv = str(v.get('style_var', ''))
    if re.search(r'[、，/：]|（可选）|如["“]', sv):
        errors.append(f'style_var 写成了描述/枚举：{sv}')
```

存量 34 + 75 个风格会一次性变红，建议**分批修 + 临时白名单**，别一次全挂。

## 附：最小合规模板

```yaml
prompt: |
  {主体描述}置于{背景环境}中，柔和光线自左上切入，画面保留细腻颗粒与手绘笔触。
  画面左上角放置中文标题「{主标题}」，字号大幅、字重醒目。
  画幅比例{画幅比例}。
  不要水印，不要真实Logo，不要电商广告感。

variables:
  - kv_var: 主体描述
    style_var: "{主体描述}"
    desc: "如：一只橘猫、一台胶片相机"
  - kv_var: 背景环境
    style_var: "{背景环境}"
    desc: "如：哑光黑摄影棚、黄昏公路"
  - kv_var: 主标题
    style_var: "{主标题}"
    desc: '如："旷野的风"、"自由之路"'
  - kv_var: 画幅比例
    style_var: "{画幅比例}"
    desc: "如：3:4 竖版、16:9 横版"
```

4 个槽位、4 条声明、逐字对应——这就是合格线。

注意上面这 4 段里：`构图/材质/光照/笔触`、`左上角` 这些**都写成了常量**，因为它们是风格的一部分，不该让用户填。
