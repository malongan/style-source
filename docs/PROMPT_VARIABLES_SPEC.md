# 提示词变量规范（PROMPT_VARIABLES_SPEC）

> 适用对象：向本仓提交风格 YAML 的 Agent / 人。
> 本文是 `AGENT_SETUP.md` 4.3 节的**强制补充**：那份模板只规定了「形态」，本文规定「语义」。
> **消费方**：WorkBuddy 插件「风格库」（id `style-source`）——用户点「插入提示词」时，插件把 `{槽位}` 换成他填的内容再插到画布上。背景见第 1 节。
> 基线数据：2026-11-02，310 个风格（`python3 scripts/audit_variables.py` 现场复核，勿照抄数字）。
>
> 一句话：**变量不是写给人看的说明书，是提示词里的可替换槽位。**

---

## 0. 三条铁律

| # | 规则 | 违反后果 |
|---|---|---|
| **R1** | 每个 `variables` 条目，其占位符必须**原样出现在 `prompt` 里** | 用户看得见输入框，填了却毫无反应 |
| **R2** | `style_var` 写**占位符本体**（`"{主体}"`），不写描述、不写候选清单 | 同上，且标签会变成一句怪话 |
| **R3** | 想让用户填什么，就在 `prompt` 里写 `{槽位}`；**不写槽位，就永远不会有输入框** | 用户抱怨「这个风格没有变量可填」 |

R3 是当前最主要的问题来源，见第 7 节统计。

## 1. 背景：这些变量最终去了哪里

改数据之前先知道消费方是谁，否则很容易把「给人看的说明」当成「给机器用的槽位」。

### 1.1 消费方：WorkBuddy 插件「风格库」

本仓的 `data/styles.json` 被一个画布式图片工作台（`image-workbench-web`）里的插件读取，插件 id `style-source`，在资源中心显示为「**风格库**」标签页。用户的实际操作是：

```
在资源中心打开「风格库」
   ↓ 栅格浏览（侧栏 320px 时 2 列，放大窗口 920px 时 7 列；按分类 chip / 关键词筛选）
点开某个风格 → 详情
   ↓ 看大图、看特点、看提示词预览
填变量输入框（这就是本文管的东西）
   ↓
点「插入参考图」→ 图片变成画布上的 image 节点
点「插入提示词」→ 替换后的完整提示词变成画布上的 prompt 节点
   ↓ 用户在画布上继续改、继续连节点、跑图
```

关键点：**用户不是在网页表单里填参数，是在创作画布上「拿一个风格来用」**。他要的是「换成我的主体/我的文案，风格不变」，所以变量的定义权属于「使用者一定会改动的部分」，而不是「作者想解释的部分」。

### 1.2 变量是怎么变成输入框的

插件里没有变量表，只有一条正则：

```js
/\{([^{}\n]{1,40})\}/g          // 扫 prompt，取出花括号里的短标识符
```

- 扫到几个槽位，就生成几个输入框；
- `variables` 只用来**给这些槽位配中文标签和示例**；
- 插入时做**纯字符串替换**：`{主体}` → 用户输入内容；
- **用户留空的槽位，原样保留 `{主体}`**（换成空串会把句子结构弄坏，模型会乱编）。

面板只有两种宽度：侧栏 240–560px（默认 320）、放大窗口约 920px。详情页里变量输入框**先摆 6 个，其余折进「展开其余 N 个变量」**——这是数量建议 3–8 的直接原因（第 5 节）。

```
┌ 风格库 · 侧栏 320px ──────┐
│ [搜索…]                   │
│ [全部 310][社媒 85][…]     │
│ ┌───┐ ┌───┐    ← 2 列     │
│ │图 │ │图 │               │
│ └───┘ └───┘               │
│ ┌ 详情 ─────────────────┐ │
│ │ 大图                   │ │
│ │ 变量                   │ │
│ │ 主体   [__________]    │ │
│ │ 主标题 [__________]    │ │
│ │ …先摆 6 个             │ │
│ │ [展开其余 2 个变量]     │ │
│ │ [插入参考图][插入提示词] │ │
│ └───────────────────────┘ │
└───────────────────────────┘
```

### 1.3 数据链路与生效时机

```
styles/{分类}/{id}.yaml
   ↓ python3 scripts/generate_data.py     （variables: list[{kv_var, style_var}] → dict{标签: 占位符}）
data/styles.json                          （全量 310 条，约 1.1MB，CORS *）
   ↓ git push → GitHub Pages 构建
https://malongan.github.io/style-source/data/styles.json
   ↓ 插件 fetch（模块级缓存，一次会话只拉一次）
用户看到的面板
```

所以：**改数据不用发插件新版本**，push 后 Pages 构建完、用户刷新页面即生效。反过来说，线上出了问题也只能靠改数据解决——插件侧不会替你兜。

### 1.4 最重要的一条：写错了是「静默失效」

插件**不做任何校验，也不会报错**。数据写法不对时，用户看到的是这三种现象之一：

| 现象 | 数据侧的原因 | 用户的理解 |
|---|---|---|
| 详情页一个输入框都没有 | prompt 里没有 `{槽位}`（R3） | 「这个风格没有变量可填」 |
| 有输入框，填了却没变化 | `style_var` 的占位符在 prompt 里不存在（R1） | 「这插件坏了」 |
| 输入框标签是 `SUBJECT`、`brand_name` | 有槽位但没声明，或标签带反引号（R2） | 「怎么是英文/乱码」 |

这也是本规范存在的理由：**错误不会在提交时暴露，只会在用户手里暴露**。第 9 节建议的那 3 条 CI 校验，就是为了把这类错误提前到 PR 阶段。

### 1.5 每条规则对应的已知失效

| 规则 | 不遵守时的真实后果 |
|---|---|
| R1 声明必须逐字出现在 prompt | 271 条声明落空，34 个风格变量全废（第 7 节） |
| R2 `style_var` 只能写占位符本体 | 430 条值写成描述，靠 key 兜底才勉强命中；标签还可能是一句怪话 |
| R3 不留槽位就没有输入框 | 31 个风格写了声明却没给槽位 → 用户看到 0 个输入框（反向的 75 个有槽位零声明，则是漏写 variables） |
| 不要用 `[方括号]` | 16 个风格的占位符永不被替换，原样插进画布 |
| 数量 3–8 | 5 个 Vigo 风格最多 24 个槽位，用户直接放弃填 |
| 标签不带 markdown | 392 条 `` `SUBJECT` `` 直接显示成标签 |
| 比例不做成变量 | 81 个风格含比例槽位，用户在文本框里填 `3:4` 既不好填，也和画布工具的比例设置重复 |

## 2. 唯一真理源

把上节的机制提炼成一条判断原则：**`prompt` 文本是唯一的真理源**。

```
扫描 prompt 文本里所有 /(\{[^{}\n]{1,40}\})/  →  生成输入框  →  插入时字符串替换
```

`variables` 只负责回答一件事：**这个槽位在面板上叫什么中文名、示例填什么**。

所以：

- `prompt` 里没有 `{xxx}` ⇒ 这个风格就是零变量，谁也没法变出输入框；
- `variables` 里写了但 `prompt` 里没有 ⇒ 这条声明是**死条目**，必须删掉或把槽位补进 prompt；
- 两边对不上时，插件会退化成「用占位符名当标签」——能用，但用户看到的是 `brand_name` 这种英文，体验差。

## 3. 三条硬规则的写法

### R1：一对一，字面量完全相同

```yaml
prompt: |
  一张{主体描述}的 X 光扫描图，骨骼以霓虹青色发光，背景为{背景色}。

variables:
  - kv_var: 主体描述
    style_var: "{主体描述}"      # ← 与 prompt 里一字不差
    desc: "如：一只猫、一台相机"
  - kv_var: 背景色
    style_var: "{背景色}"
    desc: "如：哑光黑、深空蓝"
```

不要出现「`{主体}` 声明成 `{主体对象}`」这种一字之差；不要把全角括号 `｛主体｝` 当占位符（不认）。

### R2：`style_var` 只能是占位符本体

| 写法 | 判定 |
|---|---|
| `style_var: "{主体描述}"` | ✅ 唯一正确形态 |
| `style_var: "主体描述"`（无括号） | ⚠️ 能命中（靠 key 兜底），但语义错，应改 |
| `style_var: "花体字内容，如'旷野的风'、'自由之路'"` | ❌ 这是 desc 内容，塞进了 style_var |
| `style_var: "3:4（手机壁纸）、16:9（横版海报）"` | ❌ 这是候选清单，用户没法选，等于没变量 |
| `style_var: ""` | ❌ 空值，生成脚本直接丢弃该条 |

想写示例？写进 `desc`：

```yaml
  - kv_var: 主标题
    style_var: "{主标题}"
    desc: '花体字内容，如"旷野的风"、"自由之路"'
```

### R3：先有槽位，才有变量

反面实例（本仓真实存在，`styles/creative/xray_scan.yaml`）：

```yaml
prompt: |
  An X-ray scan of a {主体对象}, bones and internal structures glowing ...
# ← 有 1 个槽位，但整个文件没有 variables
```

结果：插件只能用 `主体对象` 当标签。**这已经算好的**——它至少有槽位。真正无解的是：

```yaml
prompt: |
  An X-ray scan of a cat, bones glowing ...      # 主体写死成 cat
```

用户想换主体只能自己去改提示词。收集阶段就要把「使用者一定会换的名词」挖成槽位。

## 4. 什么该做成变量

判据只有一句：**换掉它，这个风格依然成立 ⇒ 该做成变量；换掉就不成立 ⇒ 它是风格本体，写成常量。**

### 该做（按优先级）

| 优先级 | 类别 | 示例 | 说明 |
|---|---|---|---|
| P0 | **主体** | `{主体对象}` `{人物描述}` `{产品}` | 几乎每个风格都该有；没有主体的风格用「场景」代替 |
| P1 | 主体的可变属性 | `{动作姿态}` `{服装}` `{配饰}` `{表情}` | 影响画面叙事，不是风格常量 |
| P2 | 场景 / 背景元素 | `{背景环境}` `{氛围元素}` `{季节}` | |
| P3 | 文案文字 | `{主标题}` `{副标题}` `{诗句}` `{品牌名}` | 海报/包装/社媒类必须有，且要给出「放哪里、多大」的上下文 |

### 不该做（写成常量，别给输入框）

| 类别 | 例子 | 原因 |
|---|---|---|
| 风格常量 | 配色方案、笔触、构图法、镜头、材质、光照 | 换了这个风格就不成立了 |
| **画幅 / 尺寸比例** | `{画幅比例}`、`{ASPECT_RATIO}`、「3:4 竖版」 | **比例由画布/绘图工具统一设定**，提示词里再写一遍会互相打架；让用户在文本框里填 `3:4` 也填不出规范格式 |
| 否定词 / 规避项 | `不要水印`、`避免写实摄影`、`avoid logos` | 用户不该也无法逐条开关 |
| 技术参数 | `{STYLE_FIDELITY_ANCHORS}`、`{SOURCE_CONTENT_TO_AVOID}`、`seed`、`steps` | 这是给模型看的元指令，不是给用户填的 |
| 已经被限定死的枚举 | 「3:4（手机壁纸）、16:9（横版）」塞进一个文本框 | 用户拿不到选择器，只能瞎猜格式 |
| 长句描述 | `{诗中景物构成的东方场景，如春日园林}` | 占位符名超过 40 字或含标点会被判为非法，直接不识别 |

> **关于比例**：不要在 `prompt` 里写「画幅比例{画幅比例}」这类句子，也不要把 `{ASPECT_RATIO}` 声明成变量。
> 构图需要考虑画幅时，把它写成**常量描述**（如「竖版海报构图，主体居下三分之一」），比例本身交给画布工具。
> 存量里 **81 个风格**含比例类槽位（`{ASPECT_RATIO}` 71 / `{比例}` 6 / `{画幅比例}` 4），
> 属于历史遗留，整改时**直接删掉槽位**，不要补声明。

## 5. 数量：常见 3–9 个，硬上限 12 个

（把画幅比例这类"工具侧设定"剔掉之后，多数风格会自然落在 4–9 个。）

本仓实测分布（2026-11 二次整改后，单位：风格数）：

| 占位符个数 | 0 | 1–2 | 3–6 | 7–9 | 10–12 |
|---|---|---|---|---|---|
| 风格数 | 76 | 54 | 58 | 91 | 23 |

- **0 个**（76）：纯风格演示，确实没有可填的东西，可接受。**但不能再出现「有声明却没槽位」**——那是死声明，见 R3。
- **1–2 个**（54）：偏少，通常只做了主体、漏了文案/场景。给模板留点余量比事后返工便宜。
- **7–12 个**（114）：面板是一列输入框，9 个左右是「能填完」的上限体感，再往上用户会跳过。
- **> 12 个**：**硬上限，CI 直接报错**（R5）。超过时先问「这几个字段是不是同一个位置上的多个元素」——
  `主体元素1/2`、`装饰元素1/2/3` 这种就该收成一个 `{主体元素}`，值用 `、` 或 `/` 分隔，
  分隔约定写进 `desc`。2026-11 有 7 个风格是这么从 19/17/15/14/14/13/13 降到 12 以内的。

推荐骨架（按分类选一套，不需要全部照搬）：

| 分类 | 建议变量 |
|---|---|
| 社交媒体 / 品牌KV | `主体` `主标题` `副标题` `品牌色` |
| 电商 / 印刷品 | `产品` `卖点文案` `背景场景` `主标题` |
| 编辑排版 / 字体排版 | `主标题` `正文摘句` `主体图像` |
| 时尚美容 / IP角色 | `人物描述` `服装造型` `妆容/表情` `背景环境` |
| 旅行城市 / 创意特殊 | `地点` `场景元素` `季节氛围` `主标题` |
| 科研专业 | `研究对象` `标注文字` `视图类型` |

## 6. 命名规范

| 项 | 规则 | 正例 | 反例 |
|---|---|---|---|
| 占位符名 | 中文短词（≤8 字）或 `UPPER_SNAKE_CASE`，**一个风格内不混用两种体系** | `{主体对象}`、`{SUBJECT}` | `{主体对象SUBJECT}`、`{主体-对象}` |
| 字符集 | 汉字 / 字母 / 数字 / 下划线；**不含**空格、引号、冒号、逗号、方括号、反引号 | `{brand_name}` | `{brand name}`、`{brand,name}` |
| 长度 | 建议 1–20 字符；**超过 40 直接不识别** | `{主体对象}` | `{诗中景物构成的东方场景与人物关系}` |
| `kv_var` | 面板标签，干净中文，不带 markdown | `主体对象` | `` `SUBJECT` ``、`**主体**` |
| `desc` | 一句示例或取值范围，写给用户看 | `如：一只猫、一台相机` | 空 |

统一用**半角** `{` `}`。`[方括号]`、`（全角括号）`、`{{双花括号}}` 一律不识别——
双花括号在本仓曾出现 164 处（看着像模板语法，插件只认单花括号，等于整段槽位失效），2026-11 已清零。
**只写单花括号。**

## 8. 收集流程（SOP）

顺序不能反。**先写死提示词再抽槽位**，不要「先列变量表再套进提示词」——后者就是 34 个死声明风格的成因。

1. **写 prompt**：把风格本身刻进文字（构图、配色、笔触、材质、光影、规避项），主体先写成**一个具体例子**（如 `a cat`）。
2. **标槽位**：逐个判断「这个名词换成别的东西，风格还成立吗？」成立 ⇒ 换成 `{中文短词}`。
3. **回读检查**：通读提示词，确认每个槽位在句子里位置合理、有前后文约束（例如不能只写 `{主标题}`，要写「左上角大幅中文标题`{主标题}`」）。
4. **写 variables**：顺序与提示词出现顺序一致；`style_var` = `"{槽位名}"`；`desc` 给示例。
5. **自检**（必须跑）：

```bash
python3 scripts/audit_variables.py --strict             # 有告警即退出码 1
python3 scripts/validate_style.py styles/{分类}/{id}.yaml
```

`--strict` 会把「声明落空」「值写成描述」「标签带反引号」都算失败，正是本次要清的三类问题。

6. **生成数据并复核**：`python3 scripts/generate_data.py` 后，确认该风格在 `data/styles.json` 里的 `variables` 非空且键名干净。

> 若无法本地跑脚本，提交前人工回答三个问题：
> ① 每个 `style_var` 是否能**复制粘贴**到 prompt 里搜到？② 每个 `{槽位}` 是否都有一条声明？③ 有没有哪条声明的值是一句人话/一串弹幕式枚举？

## 9. CI 门禁（已实现）

`scripts/validate_style.py` 里的 `check_variables_semantics()` 现在跑 5 条规则，全部是 **error**
（有错即 exit 1，PR 直接红）：

| 规则 | 检查 | 为什么 |
|---|---|---|
| **R1** | 每条 `style_var` 必须逐字出现在 `prompt` 里 | 不在 prompt 里的声明 = 用户填了不生效，而且没有任何报错 |
| **R2** | `style_var` 只能是 `{占位符}` 本体，不能是候选清单/一句人话 | 写成枚举值后它连自己都对不上 prompt，是「静默失效」的头号来源 |
| **R3** | `prompt` 里每个槽位都必须有声明 | 漏声明不会出输入框，且标签退化成英文占位符名（`subject_description`） |
| **R4** | `kv_var` 必须含中文（`ALLOW_EN_KV` 白名单除外） | 面板是中文界面，一整片 `SUBJECT` / `MAIN_TEXT` 既占宽又和占位符名混淆 |
| **R5** | 变量数 ≤ `MAX_VARIABLES`（12） | 超过 12 个用户不会填完，根源通常是 `元素1/2/3` 该合并没合并 |

```bash
python3 scripts/validate_style.py          # 单文件校验 + 汇总
python3 scripts/validate_all.py --strict   # CI 用的入口，有 error 即失败
python3 scripts/audit_variables.py         # 全库体检报告（只读，不当闸门）
```

配套的整改脚本（都默认 dry-run，改动逐条打印，确认后加 `--apply`）：

| 脚本 | 用途 |
|---|---|
| `scripts/migrate_variables_spec.py` | 按规范批量整改；`--labels-only` 只换英文标签，`--check` 校验词典覆盖率 |
| `scripts/fix_dirty_slots.py` | 把「说明书当占位符名」的槽位改成短名 + 原内容降级成 `desc` |

## 附：最小合规模板

```yaml
prompt: |
  {主体描述}置于{背景环境}中，竖版构图、主体居下三分之一，柔和光线自左上切入，
  画面保留细腻颗粒与手绘笔触。
  画面左上角放置中文标题「{主标题}」，字号大幅、字重醒目。
  不要水印，不要真实Logo，不要电商广告感。

variables:
  - kv_var: 主体描述
    style_var: "{主体描述}"
    desc: "如：一只橘猫、一台胶片相机"
  - kv_var: 背景环境
    style_var: "{背景环境}"
    desc: "如：哑光黑摄影棚、黄昏公路"
  - kv_var: 主标题
    style_var: "{主标题}"
    desc: '如："旷野的风"、"自由之路"'
```

3 个槽位、3 条声明、逐字对应——这就是合格线。

注意：`竖版构图`、`主体居下三分之一`、`左上角`、`光线自左上`、`颗粒与手绘笔触` **全部写成常量**——
它们是风格的一部分，不该让用户填；而**画幅比例本身不做成变量**，由画布工具设定。
